# Порядок загрузки и сравнение с pip

Проверка выполнена 09.11.2026 для requests==2.32.3 в отдельном каталоге,
CPython 3.12.14, Windows AMD64. Приложение Java pip не вызывает.
Штатный pip использован отдельно, только для сравнения:

```text
python -m pip install --ignore-installed --only-binary=:all: --target TARGET requests==2.32.3
```

InstallOrder.of выдаёт детерминированный топологический порядок:

```text
certifi==2026.10.23
charset-normalizer==3.5.2
idna==3.20
urllib3==2.8.0
requests==2.32.3
```

В журнале pip строка Installing collected packages показывает реальный
порядок установки. Исходный журнал: comparison/requests-pip-install.txt.
Обе программы ставят четыре независимые библиотеки до requests.
Порядок между этими четырьмя листьями может различаться: рёбер между ними
нет, поэтому любой их порядок корректен. Наша программа сортирует
равноправные готовые вершины по имени, pip использует собственный порядок.

Порядок скачивания файлов и порядок установки - разные операции.
Инструмент выводит зависимость-первый порядок загрузки/установки.
Очередь HTTP-запросов соответствует BFS и не обязана совпадать с ним.
При цикле корректного полного топологического порядка нет: выводится
явная ошибка, хотя сам циклический граф строится и визуализируется.

Тестовый ромб: A -> B C, B -> D, C -> D. BFS: A, B, C, D.
Порядок установки: D, B, C, A. Для E -> A: D, B, C, A, E.
Для I: I. Самоссылка F и цикл G-H: явная ошибка порядка.

https://pip.pypa.io/en/stable/cli/pip_install/#installation-order
