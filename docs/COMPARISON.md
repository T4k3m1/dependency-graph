# Сравнение зависимостей с pip

Дата: 09.11.2026. Эталон: CPython 3.12.14, Windows AMD64.
Каждый пакет установлен настоящим pip в отдельную временную папку
с --ignore-installed --only-binary=:all:. Исходные журналы сохранены
в comparison/*-pip-install.txt. Установка не меняла глобальную среду Python.

Штатный pip inspect --path TARGET дал машиночитаемые метаданные среды.
Для привычного дерева применён внешний инструмент pipdeptree:

```text
python -m pipdeptree --path TARGET --packages PACKAGE --warn silence
```

Pip сам не предоставляет команды dependency:tree, аналогичной Maven.
Поэтому отдельно использованы штатная инспекция pip и дерево pipdeptree.
Их код не включён в Java-приложение и не вызывается им при анализе.

| Корень | Вершины | Рёбра | Результат сравнения |
| --- | --- | --- | --- |
| requests==2.32.3 | 5 | 4 | Совпадают версии, вершины и рёбра |
| rich==13.9.4 | 4 | 3 | Совпадают, включая транзитивный mdurl |
| packaging==24.2 | 1 | 0 | Совпадают, зависимостей нет |

Для каждого примера сохранены исходное дерево pip, D2 нашего приложения,
его список смежности BFS и порядок установки в comparison/*.txt.
Вершины и рёбра сравнивались программно после нормализации имён пакетов.
Проверено, что каждая зависимость расположена в нашем порядке раньше родителя.
Порядок между независимыми библиотеками отличается от pip, это допустимо;
объяснение и журнал приведены в ORDER_COMPARISON.md.

## Область поддержки

Это учебный анализатор, не полный аналог pip resolver.
Поддерживаются стабильные числовые версии и их ограничения, обычные
Requires-Dist, распространённые environment markers с and/or/скобками,
нормализация имён, Requires-Python и исключение yanked-кандидатов.
Корневая версия задана пользователем, транзитивно выбирается наиболее
новая совместимая стабильная версия. Загрузка данных не устанавливает пакеты.

Полный PEP 440 (pre/dev/post/local/epoch), extras, прямые URL и backtracking
не реализованы. Неподдержанные применимые конструкции дают явную ошибку.
Если более позднее ограничение конфликтует с уже выбранной версией,
выдаётся ошибка конфликта вместо подмены или некорректного графа.
Предыдущие версии при конфликте автоматически не перебираются.
Учитывается Requires-Python; совместимость конкретного wheel по ABI/платформе
не моделируется. Версия может иметь совместимый исходный дистрибутив.
Маркеры используют фиксированную среду CPython 3.12.14 Windows AMD64,
без extras; platform_release/platform_version не поддержаны и дают ошибку.

Для новых PyPI-релизов использовано поле releases JSON API. Оно помечено
в документации PyPI как deprecated: при его удалении понадобится переход
на индекс API. Ошибка отсутствующего поля будет явной, а не пустым графом.
Метаданные на PyPI могут изменяться; выбор транзитивных версий при повторе
позднее может дать другой результат. Сохранённые выводы фиксируют проверку.
