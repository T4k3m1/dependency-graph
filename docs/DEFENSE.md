# Подготовка к защите варианта 11

## Краткое описание

«Инструмент написан на Java и анализирует зависимости пакетов Python.
Пять параметров задаются опциями командной строки. Метаданные заданной
версии получаются непосредственно через JSON API PyPI. HTTP, JSON,
ограничения версий и условия среды обрабатывает наш код средствами JDK.
Pip не вызывается для построения графа. BFS реализован с рекурсией
по уровням. Граф преобразуется в D2 и сохраняется в SVG».

## Что означают параметры

--package: имя пакета, например requests. --version: точная версия 2.32.3.
--repository: https://pypi.org либо путь к тестовому файлу.
--test-mode: true/false. --output: имя создаваемого SVG.
--stage: дополнительный выбор демонстрационного этапа, по умолчанию 5.
Это не CSV-конфигурация: вариант 11 требует именно опции командной строки.

В тестовом режиме имена состоят из A-Z; версия проверяется, но символические
вершины тестового графа не имеют версий. В сети вершина обозначается
name==version: разные версии являются разными идентичностями.

## BFS с рекурсией

Вместо рекурсивного обхода каждого потомка сначала обрабатывается весь
текущий уровень. Прямые зависимости собираются в список следующего уровня,
затем Graph.level вызывает себя ровно для этого списка.
Для A -> B C, B -> D, C -> D порядок A, B, C, D.
Это BFS: сначала расстояние 0 от корня, затем 1, затем 2.
Если рекурсивно обрабатывать отдельного потомка до его братьев,
получится DFS, что варианту 11 не соответствует.

Вершина отмечается как обнаруженная до добавления на следующий уровень.
Поэтому D не обрабатывается дважды, а G -> H -> G не вызывает бесконечную
рекурсию. Оба ребра цикла остаются в графе. Самоссылка F -> F тоже сохраняется.
Число рекурсивных вызовов зависит от количества уровней, не от ширины.
Есть тест на 4001 вершину при глубине 2 и защита от глубины более 512 уровней.
Графовый обход занимает O(V + E), не считая сети и разбора метаданных.

## Получение зависимостей

PyPI JSON API /pypi/name/version/json возвращает данные конкретного релиза.
В info.requires_dist находятся декларации зависимостей. Requirement
разделяет имя, ограничение версии и маркер среды. Versions проверяет
>=, <=, >, <, ==, !=, ~=, === и допустимые wildcard-префиксы.
PypiRepository выбирает наиболее новый совместимый неотозванный стабильный
числовой релиз. Заданная версия корня не заменяется последней.
Для условий среды используется CPython 3.12.14, Windows AMD64, без extras.
Эти условия фиксированы и не зависят от установленного у пользователя Python.

Пример: rich зависит от markdown-it-py, а тот - от mdurl.
Следовательно, mdurl является транзитивной зависимостью rich.
HTTP-ошибки, несовместимые версии и неподдержанные конструкции не скрываются.

## Порядок загрузки

BFS отвечает, в каком порядке исследуются вершины. Порядок загрузки/установки
требует, чтобы зависимость предшествовала её потребителю.
InstallOrder.of использует алгоритм Кана: сначала доступны листья,
после их удаления становятся доступны родители. Из равноправных вершин
выбирается первая по алфавиту. Для ромба: D, B, C, A.
Сложность с очередью приоритетов: O((V + E) log V).

В цикле нельзя поставить каждый пакет раньше зависящего от него:
полный топологический порядок не существует. Программа сообщает об этом,
но разрешает построить и нарисовать циклический граф. Реальный pip может
выбирать собственный порядок внутри цикла, не соблюдая все рёбра сразу.
Скачивание файлов по HTTP - отдельная операция; его порядок не называется
топологической установкой. В сравнении с pip рассматривается строка
Installing collected packages, а не последовательность скачивания wheel.

## D2 и SVG

D2 - текстовый язык диаграмм. node0: "requests==2.32.3" создаёт подпись,
node0 -> node1 задаёт ребро от пакета к его зависимости.
Visualization.d2 формирует текст самостоятельно. Visualization.save
сохраняет .d2 и вызывает установленный D2 только для преобразования в SVG.
Это не нарушает запрет на готовое получение зависимостей: D2 не знает
о PyPI и получает уже готовый граф. SVG - векторное изображение,
которое можно открыть обычным браузером и масштабировать без потери качества.

## Сценарий показа

1. Запустить test.bat: тесты на Java, без JUnit и внешней сети.
2. Показать --stage 1: пять параметров ключ=значение.
3. Показать --stage 2 для requests версии 2.32.3: прямые зависимости.
4. Показать --stage 3 для A: порядок BFS A, B, C, D.
5. Показать --stage 4 для A: D, B, C, A.
6. Показать этапы 3 и 5 для F, G, I: самоссылка, цикл, лист.
7. Показать ошибку этапа 4 для G.
8. Открыть SVG requests, rich и packaging. Сравнить с docs/comparison.
9. По очереди испортить имя, путь, флаг, версию и расширение выходного файла.
10. Показать git log: отдельный коммит для каждого из пяти этапов.

Полные команды находятся в README. Перед защитой выполните их самостоятельно
и научитесь объяснять отличие BFS от DFS и топологического порядка.
Границы поддержки не следует выдавать за полную совместимость с pip resolver.
